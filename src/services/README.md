# Будущие адаптеры Voyz

Интерфейс использует `StoreProvider`, а переходы — чистую функцию `execute` в `domain/commands.ts`. Текущая реализация хранит состояние в AsyncStorage; внешних запросов нет.

При подключении серверов разделить адаптеры: аккаунт и профиль Voyz; туры и выезды; бронирования и допуск к общему чату; сообщения; справочник мест гида; проживание и остатки; поддержка; уведомления.

Сохранение локального состояния не заменяет серверные проверки. Резервы, таймеры, лимиты, версии условий, права доступа и атомарный учёт мест должны проверяться на сервере. Демокоманды с `demo: true` и экран Demo не должны попасть в рабочий продукт без явного режима демонстрации.

Не копировать в Friends платёжные реквизиты, документы и гостиничные данные. Личная заявка, социальный план, бронь тура и гостиничная бронь — отдельные сущности. Коммерческий чат открывается по политике бронирования Voyz, а не по локальной заявке.
